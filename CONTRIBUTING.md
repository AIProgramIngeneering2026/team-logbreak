# Участие в разработке LogBreak

## Ветки

- `main` всегда содержит проверенную версию проекта.
- Для каждой задачи создаётся отдельная ветка от актуального `main`.
- Формат имени: `<тип>/<номер-issue>-<краткое-описание>`.
- Допустимые типы: `feature`, `fix`, `docs`, `test`, `chore`.
- Пример: `docs/3-job-lifecycle`.

## Коммиты

- Один коммит описывает одно логическое изменение.
- Сообщение пишется в повелительном наклонении и объясняет результат, например `Добавить сценарий отмены Job`.
- В конце сообщения или описании PR указывается issue: `Refs #3` или `Closes #3`.
- Секреты, локальные настройки IDE и сгенерированные файлы не коммитятся.

## Pull Request и review

1. Автор обновляет ветку относительно `main` и открывает PR, связанный с issue.
2. В описании автор перечисляет изменения и способ проверки.
3. Другой участник проверяет требования, тесты, читаемость и отсутствие изменений вне задачи.
4. Замечания по существу исправляются в той же ветке; обсуждения должны быть разрешены до merge.
5. PR вливается только после одобрения другого участника и зелёных автоматических проверок. Force push в общие ветки запрещён.

## Definition of Done

Задача считается выполненной, когда:

- выполнены все критерии приёмки из issue;
- добавлены или обновлены позитивные и негативные тесты для изменённого поведения;
- тесты и статические проверки запускаются одной командой и проходят локально и в CI;
- публичные контракты и документация обновлены;
- ошибки имеют единый машиночитаемый формат;
- в коде, логах и репозитории нет секретов и персональных данных;
- PR связан с issue, получил содержательное review и влит в `main`;
- проект по-прежнему запускается из чистого клона по README.
