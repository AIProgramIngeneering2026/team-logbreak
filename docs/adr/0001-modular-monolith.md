# ADR-0001: Модульный монолит с Tool внутри процесса

- Дата: 2026-11-15
- Статус: принят

## Контекст и ограничения

Первая версия IndieFashion Radar должна запускать сбор из Telegram и сайтов, нормализовать данные и обслуживать HTTP API. Команда небольшая, отдельных требований к независимому масштабированию адаптеров пока нет. При этом код источников должен быть заменяемым и не должен проникать в Dispatcher.

## Решение

Реализовать HTTP API, Dispatcher, Registry, нормализацию и реализации Tool как модули одного приложения. Фоновый обработчик может быть отдельным процессом того же приложения, но использует те же доменные контракты и хранилище. Registry выдаёт Tool по типу разрешённого источника, а взаимодействие идёт только через [контракт Tool](../tool-contract.md).

Границы модулей не зависят от сетевого транспорта. Это позволяет позднее вынести адаптер в сервис без изменения Dispatcher: вместо локальной реализации Registry зарегистрирует прокси, соблюдающий тот же контракт.

## Рассмотренные альтернативы

1. Отдельный микросервис для каждого типа источника. Даёт независимое развёртывание и масштабирование, но добавляет сетевые отказы, версионирование контрактов и эксплуатационную стоимость до появления нагрузки.
2. Вызовы Telegram и сайтов прямо из Dispatcher. Проще в самом начале, но связывает оркестрацию с протоколами источников и делает тестирование с fake-реализациями сложнее.
3. Сторонний оркестратор задач как основа системы. Полезен для больших графов, но избыточен для линейного жизненного цикла текущего Job.

## Цена решения

- Сбой или утечка памяти в адаптере может повлиять на весь worker-процесс.
- Нельзя независимо масштабировать один тип Tool без запуска ещё одного экземпляра приложения.
- Нужно явно контролировать зависимости между модулями и не обходить контракт прямыми вызовами.

Взамен первая версия проще в разработке, локальном запуске и наблюдении, а fake Tool позволяет воспроизводимо тестировать timeout, `429` и повреждённый ответ.

## Условия пересмотра

Решение пересматривается, если один адаптер требует отдельного стека или секретов, его нагрузка отличается на порядок, сбои регулярно влияют на остальные источники либо появляется требование независимого развёртывания. Перед выделением сервиса собираются метрики времени, ошибок и очереди по каждому Tool.
